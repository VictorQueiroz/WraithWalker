# WraithWalker

> Generated by rulesync from `.rulesync/rules/overview.md`. Do not edit this file directly — edit the source rule and run `npm run ai:generate`.

Chrome extension for capturing, storing, and replaying network fixtures from the local filesystem. Monorepo with 6 packages: extension, native-host, mcp-server, cli, core, agent.

## Build & Test

```bash
npm run build      # build all packages
npm test           # run unit, contract, and smoke tests
npm run typecheck  # type-check all packages
```

Coverage thresholds: 90/90/95/80 (statements/lines/functions/branches) for extension and native-host. CLI and MCP server have relaxed branch thresholds.

## Architecture

- `packages/extension` — Chrome MV3 extension (TypeScript, `.ts`, browser target)
- `packages/native-host` — Node.js native messaging host (TypeScript, `.mts`, Node target)
- `packages/mcp-server` — MCP server (TypeScript, `.mts`, Node target)
- `packages/agent` — headless AI assistant (TypeScript, `.mts`, Node target): Vercel AI Gateway chat agent (AI SDK 7, default model `deepseek/deepseek-v4-pro` at `xhigh` reasoning), RAG over captured fixtures via embeddings in SQLite (`node:sqlite`), conversation persistence, and the `/agent/*` HTTP routes mounted into `wraithwalker serve`. Gateway credentials load from `~/.config/wraithwalker/.env` (`AI_GATEWAY_API_KEY`); the repo-root `.env` provides a key for live e2e tests. Projects group captured origins by registrable domain and link third-party origins captured under the same browser tabs.
- `packages/cli` — CLI tool (TypeScript, `.mts`, Node target, imports from mcp-server and native-host via `exports` maps)

The extension uses dependency injection throughout — every module exports a `createXxx()` factory that accepts an interface of dependencies. Tests use in-memory mocks (`MemoryDirectoryHandle`, `MemoryFileHandle`) for the File System Access API.

## Code Navigation — Serena MCP

Serena runs a TypeScript language server over this repo (config in `.serena/project.yml`) and exposes symbol-level tools. Prefer them over reading whole files: this is a 6-package monorepo where a single `createXxx()` factory, its interface, and its tests live in different packages, and full-file reads burn context fast.

Use Serena when:

- **Locating a symbol** — `find_symbol` instead of grepping for a name across `packages/*`.
- **Changing a shared type or factory interface** — `find_referencing_symbols` first, to catch every call site across `extension`, `native-host`, `mcp-server`, and `cli` (they cross package boundaries via `exports` maps, so a naive grep misses re-exports).
- **Editing a known function or class** — `replace_symbol_body` / `insert_after_symbol` rather than rewriting the surrounding file.
- **Orienting in an unfamiliar package** — `get_symbols_overview` before opening files.

Plain file reads remain the right tool for config, Markdown, and `manifest.json`, which the language server does not index.
